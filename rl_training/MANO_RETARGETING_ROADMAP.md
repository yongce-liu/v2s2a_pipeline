# MANO + object trajectory learned-retargeting roadmap

## Status

This is a **future implementation plan**, not the current training input contract.
The current priority is improving and benchmarking RL from the already-retargeted
robot-hand trajectory plus the object trajectory.

## Goal

Eventually replace the fixed offline robot-joint reference with a learned,
embodiment-conditioned retargeter while preserving closed-loop physics control:

```text
MANO hand trajectory + object SE(3) trajectory + object geometry
                              |
                    temporal MANO-object encoder
                              |
                 embodiment-conditioned retarget head
                              |
                       differentiable FK
                              |
                    robot reference trajectory
                              |
                      residual RL policy
                              |
                         robot actions
```

The model must not infer actions from MANO alone. Object motion and geometry are
required because human pose does not uniquely determine feasible robot contacts,
forces, or joint configurations.

## Available source signals

`trajectory_keypoints.npz` already provides the main supervision candidates:

- world-frame MANO vertices and faces;
- 45-D MANO finger pose;
- MANO global wrist orientation and shape coefficients;
- wrist and fingertip trajectories;
- object SE(3) trajectory;
- optional contact labels.

The existing `trajectory_kinematic.npz` provides robot joint targets generated by
the optimization-based retargeter and can serve as teacher data.

## Staged implementation

### Stage 1: supervised retarget-head distillation

Train a temporal encoder and robot-specific decoder against existing IK outputs.
Use differentiable forward kinematics rather than joint regression alone.

Losses:

- robot keypoint/FK loss;
- teacher joint-position loss;
- joint-limit penalty;
- temporal velocity and acceleration smoothness;
- self/object penetration penalty;
- object-frame contact-anchor loss;
- object-relative hand-pose loss.

Acceptance criteria:

- robot keypoint error no worse than the offline retarget baseline;
- no increase in joint-limit violations or penetration;
- stable predictions on held-out clips and temporal perturbations.

### Stage 2: frozen learned reference + residual RL

Freeze the learned retargeter and replace the offline robot reference consumed by
the current trajectory-tracking environment. Keep the actor closed-loop: it must
observe actual robot/object state and predict residual joint-position targets.

Compare:

1. offline IK reference + RL;
2. learned reference, frozen + RL.

### Stage 3: constrained joint fine-tuning

Jointly update the retarget head and residual policy only after Stage 2 matches the
baseline. Retain teacher, FK, contact, collision, object-trajectory and temporal
losses so the reference cannot drift toward simulator exploits.

Compare:

1. offline IK + RL;
2. learned retarget frozen + RL;
3. jointly fine-tuned retarget + RL.

## Suggested architecture

- MANO encoder: 21 joints or sampled mesh vertices, velocities, wrist pose, shape;
- object encoder: SE(3) sequence plus point-cloud/SDF embedding;
- temporal backbone: TCN or Transformer with causal and finite-look-ahead modes;
- embodiment input: joint limits, link/keypoint geometry and a robot ID/morphology embedding;
- heads: robot joint reference, contact probability/surface anchor, confidence;
- controller: current residual joint-position policy, not direct torque regression.

## Evaluation and go/no-go gate

Measure on fixed train/validation/test clips:

- unassisted frame-0 task success rate;
- object position/orientation RMSE;
- robot keypoint error;
- contact-transition F1 and slip;
- penetration and joint-limit violation rate;
- recovery from perturbed initial states;
- retargeting inference time.

Proceed with end-to-end fine-tuning only if the learned frozen retargeter matches
the offline-retarget RL baseline on object tracking and success, while materially
reducing retargeting time. Otherwise retain the two-stage architecture.

## Relevant open-source references

- [DexTrack](https://github.com/Meowuu7/DexTrack): successful trajectory mining and IL/RL iteration;
- [dex-retargeting](https://github.com/dexsuite/dex-retargeting): optimization teacher/baseline;
- [DexMV](https://github.com/yzqin/dexmv-sim): human-hand/video to robot demonstrations;
- [SkillMimic](https://github.com/wyhuai/SkillMimic): reference-state initialization, relative-motion and contact-graph objectives;
- [Isaac Lab](https://github.com/isaac-sim/IsaacLab): simulation, curriculum and policy-training framework.
