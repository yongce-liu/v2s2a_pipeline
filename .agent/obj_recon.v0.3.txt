● pointmap_scale/shift 由每个视图的 preprocess_image
  独立计算，外部点图路径同样存在——metric
  位姿解码成立。情况已经摸清，整体状态和规划如下（实现前有个取舍要你定）：

  摸底结论

  1. 安装方式：不能直接 pip+git，必须按上游仓库的方式 vendored 子包 ✅ 已做
  - pkgs/MV-SAM3D 已作为 submodule 加入（与 pkgs/sam-3d-objects 并列）
  - 原因：MV-SAM3D 魔改了 sam3d_objects 包（新增
    pipeline/multi_view_weighted.py、multi_view_utils.py、pose_align/，改了
    inference_pipeline.py），用 pip install git+... 会按 name = "sam3d_objects"
    解析依赖——它 hard-pin torch 2.5.1+cu121、kaolin 0.17.0 等，和 obj_recon
    现有的 torch 2.8+cu128 / RTX 5090 依赖矩阵完全冲突，会和你 uv override
    修复过的 wheel 矩阵打架。
  - 正确做法 = 和上游 sam-3d-objects 一样：[tool.uv.sources] sam3d-objects-mv = 
    { path = "../pkgs/MV-SAM3D", editable = true } + 复用现有 override
    矩阵。它用的模型权重和单视角完全相同（同上游 checkpoints），故无需新权重。

  2. geometry 输出复用（你最新的要求）——成立，且是官方外部 pointmap 路径
  - run_multi_view(view_pointmaps=...) 直接吃外部 per-view point map；注释里明确
    DA3/MoGe 约定一致（OpenCV x→ / y↓ / z前），代码统一做 (-x,-y,z) →
    PyTorch3D。geometry 的 MoGe points.npy 可以直接喂，不用改坐标。
  - 注释还确认：外部 pointmap
    路径不依赖内参（内参从点图每视图独立推断，pointmap_scale/shift
    也逐视图算）——metric 位姿没问题。
  - ⚠️ 唯一要丢的：官方 --da3_output 还顺带提供 1) extrinsics（相机外参，仅供
    latent-visibility 分析和 pose_opt 的场景对齐）和 2)
    scene.glb（场景点云用于最终 pose optimization）。这两块如果您默认
    stage2_weight_source=entropy，都不是必需。

  3. 默认方案（视差大的前 N 帧 MV → 密集帧 pose 由 pose_estimation 补）— 
  技术路径是通的
  - Stage1(multidiffusion→加权) + Stage2(entropy 加权) + mesh输出 glb、view0
    位姿 rotation/translation/scale + 每帧解码位姿
    all_view_poses_decoded，一次拿到「fusionmesh + 每视图 metric 位姿」。

  实现前需要你定的取舍

  MV-SAM3D 镜像的重量依赖（finetuned generator、TRELLIS
  decode、layout_post_optimization）和单视角仓库同名同结构，但 pose_optimization
  希望在「scene 完整点云」上跑——它用 DA3 背景+物体点云。用 geometry
  的话背景=仅物体 mask 内的 MoGe 点。
