● 目前 pose_estimation 还不支持真正的“分段估计”或“按多视角关键帧分别估计”。

  当前已有能力

  它现在的模式是：

  1. 输入一段完整视频的 frames.json
  2. 使用一个融合后的 mesh
  3. 通过单个 --init-frame 做一次 FoundationPose register
  4. 从初始化帧：
     - 向后正序跟踪
     - 向前反序跟踪

  对应实现位于：

  - 参数定义：pose_estimation/pose_estimation/workflow.py:54
  - 前后向帧拆分：pose_estimation/pose_estimation/workflow.py:424
  - 初始化与正向跟踪：pose_estimation/pose_estimation/workflow.py:477
  - 反向跟踪：pose_estimation/pose_estimation/workflow.py:501

  因此，--init-frame 44 可以从第 44 帧向两边跟踪，但这仍然是一条连续 tracking 
  链，不是把 [0, 44, 88] 分成多个区间并分别初始化。

  现阶段缺少的能力

  CLI 目前没有以下参数或数据结构：

  - --keyframes 0 44 88
  - --segment-start / --segment-end
  - 多个 anchor/init frame
  - 每段独立 register
  - segment/view 级输出路径
  - 从 obj_recon/view_poses.json 读取关键帧定义

  虽然有 --reinit-every N，但它只是按照全局帧号取模周期性重新注册，不能精确使用
  obj_recon 选择出的关键帧，所以不能等价替代分段支持。

  参数见 pose_estimation/pose_estimation/workflow.py:54-111。

  与 obj_recon 多视角模式的衔接现状

  obj_recon 多视角当前会输出：

  meshes/mv/<object>/<object>.obj
  meshes/mv/<object>/<object>.glb
  layout.json
  view_poses.json

  相关代码在 obj_recon/obj_recon/multiview.py:300-346。

  其中：

  - layout.json 只表达 view-0 参考位姿。
  - view_poses.json 设计上用于保存各关键帧位姿。
  - 但当前 MV-SAM3D 的 all_view_poses_raw 通常没有填充，因此往往只有 view-0。
  - 注释虽然说剩余关键帧位姿由 pose_estimation tracking 补齐，但 pose_estimation
    尚未实现针对关键帧集合的专门编排。

  所以现在可以把融合 mesh 交给
  pose_estimation，从一个初始化帧跟踪整段视频；但无法做到：

  anchor k0 ── track ── midpoint
                      midpoint ── track backward ── anchor k1
  anchor k1 ── track ── midpoint
  ...

  这种真正的分段、多 anchor 估计。

  当前输出也不适合多段独立运行

  输出固定为：

  outputs/<clip>/pose_estimation/
  ├── config.json
  ├── poses.json
  ├── poses/
  │   ├── 000000.txt
  │   └── ...
  └── vis.mp4

  定义见：

  - pose_estimation/pose_estimation/workflow.py:400-410
  - pose_estimation/pose_estimation/workflow.py:526-579

  路径中没有 segment_id、view_id 或 keyframe_id。如果用不同 --init-frame
  多次运行，同一输出目录会互相覆盖。

  结论

  ┌───────────────────────────┬──────────┐
  │           能力            │ 当前状态 │
  ├───────────────────────────┼──────────┤
  │ 单初始化帧、双向 tracking │ 支持     │
  ├───────────────────────────┼──────────┤
  │ 周期性 reinit             │ 支持     │
  ├───────────────────────────┼──────────┤
  │ 使用多视角融合 mesh       │ 可以     │
  ├───────────────────────────┼──────────┤
  │ 根据关键帧列表重新初始化  │ 不支持   │
  ├───────────────────────────┼──────────┤
  │ 指定 [start, end] 子区间  │ 不支持   │
  ├───────────────────────────┼──────────┤
  │ 多 anchor 分段 tracking   │ 不支持   │
  ├───────────────────────────┼──────────┤
  │ 自动消费 view_poses.json  │ 不支持   │
  ├───────────────────────────┼──────────┤
  │ 分段结果合并及冲突选择    │ 不支持   │
  └───────────────────────────┴──────────┘

  要和新的 obj_recon 多视角关键帧能力正确对接，下一步应在 pose_estimation 增加：

  1. 读取 view_poses.json 或显式 --keyframes。
  2. 每个关键帧独立 register。
  3. 相邻关键帧之间分别前向/反向跟踪。
  4. 在区间中点或按置信度合并两侧结果。
  5. 最终仍输出一套连续的 poses/{frame}.txt，同时在 poses.json 记录
     segment_id、anchor_frame 和 tracking direction。
